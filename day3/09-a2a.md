# 09 — A2A: agent ↔ agent

**Edit:** `src/api.py` (the card) and `src/a2a_client.py` · **Spec:** https://a2a-protocol.org

## The clean split, one more time

```
                 A2A
        ┌─────────────────────┐
        │                     ▼
  Your agent            Peer's agent
        │                     │
       MCP                   MCP
        │                     │
      tools                 tools
```

**MCP:** an agent reaching *down* into capabilities. **A2A:** independent agents reaching *across* to each other — different owners, different stacks, no shared code. A2A 1.0 is a stable protocol with official SDKs (Python, JS, Go, Java, .NET, Rust); its discovery mechanism is the **Agent Card**, served at a well-known path:

```
GET /.well-known/agent-card.json
```

The card advertises: who I am, what I can do (skills), where to reach me (`url`), and how (input/output modes, capabilities). Discovery decouples *"I know where you live"* from *"I know how to use you"* — the client learns the endpoint FROM the card, never hardcodes it.

## Scope honesty

Today we implement **card-based discovery + delegation over your OpenResponses endpoint**: a real, spec-shaped Agent Card whose `url` points at your `/v1/responses`. The full A2A task protocol (task ids, lifecycle states, streaming) via the official `a2a-sdk` is the bonus for fast finishers — the concepts are identical, the ceremony is larger.

## Your task

**1. The card** — replace the stub in `src/api.py`. Serve at `/.well-known/agent-card.json`:

```json
{
  "protocolVersion": "1.0",
  "name": "<STUDENT_NAME>-agent",
  "description": "…what makes YOUR agent worth delegating to…",
  "url": "<PUBLIC_URL>/v1/responses",
  "version": "0.1.0",
  "capabilities": {"streaming": false},
  "defaultInputModes": ["text/plain"],
  "defaultOutputModes": ["text/plain"],
  "skills": [{"id": "…", "name": "…", "description": "…", "tags": ["…"]}]
}
```

`STUDENT_NAME` and `PUBLIC_URL` come from the environment (`.env`) — the same image must produce a *different* card per student on the shared server. Config at run time, not baked at build time: Docker lesson, reprise. List your skill from 02 in `skills` — the card is your advertisement.

**2. The client** — `src/a2a_client.py`:

```
discover(peer_url)  ── GET card ── print name + skills ── return card
delegate(card, task) ── POST {"input": task} to card["url"] ── return output_text
```
